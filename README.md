# 收音对比台 / VoiceBench

[English](README.en.md) · [版本记录](CHANGELOG.md) · [开源许可](LICENSE)

在本机导入不同设备的录音，自动生成可追溯的评分、场景分组比较及报告。v1.2 支持不提供原稿的音质比较，添加正确原稿后再检查内容识别。适合近距离人声收音设备、麦克风结构及固件版本的内部研发比较。

## 使用

双击 **启动收音对比台.command**，会打开本机浏览器。第一次导入后模型需要加载，转写时间随音频长度和电脑性能变化；完成后可从左侧重新打开测试。

1. 导入 1～20 份录音；每份不超过 100 MB、10 分钟，每批不超过 500 MB。
2. 填写设备与场景。重复录音使用同一设备名；相同场景的录音可比较音质。
3. 原稿可选：没有原稿时直接分析音质；需要检查内容时展开“原稿与关键词”，填写共用或专属原稿（支持 UTF-8 TXT）。不同原稿的字错率不会合并排名。
4. 有正确原稿时可指定重点核对的词句，例如数字、人名、型号和否定词。
5. 如实际测试条件一致，勾选条件确认，再开始分析。
6. 查看分组表、逐字对照、质量评分和回听定位，导出 HTML 报告、CSV 或完整 JSON。HTML 是独立静态报告，可在浏览器打印为 PDF；导出报告不内嵌原音频。

录音与原稿只保存在本机 `data/jobs/`。模型在本机运行，不调用在线识别 API。关闭浏览器不会停止正在分析的任务；电脑重启或服务退出后，已完成结果仍保留，未完成项可从历史记录重试。

试听文件为选定声道的 16 kHz 单声道分析副本，不是原文件的逐位复制；源文件单独原样保存。匹配试听音量只施加固定增益，以 -23 dBFS RMS 为目标、保留采样峰值余量，不做降噪，不等同于 LUFS 等响匹配。各项原始电平指标在匹配前测量。

## 分数解释

| 指标 | 定义与限制 |
| --- | --- |
| CER 字错率 | 替换、漏字和插入的字符总数 / 原稿字符数。中文及英文都按字符；CER 可能大于 100%。 |
| 内容保真分 | `max(0, 100*(1-CER))`，是转写衍生分，不能解释为人工听懂百分比。 |
| 关键词正确率 | 在原稿每个关键词出现的位置检查连续的正确对齐。原稿没有的关键词排除。 |
| DNSMOS P.835 | 非个性化模型预测的人声、背景与整体质量；不是人工 MOS、可懂度或真实声学 SNR。 |
| LUFS / dBTP | 在选定声道、原始采样率下用 FFmpeg 分析；静音时可能无有效值。 |
| 接近满刻度采样 | 原采样率下绝对值 ≥ 0.999 的比例；连续 ≥ 3 个采样列为疑似削波，不能覆盖全部失真类型。 |
| 低能量时段 | 20 ms 帧 RMS 低于 -50 dBFS；不能直接解释为没有说话、掉字或硬件断音。 |
| 频谱 | 文件本身的平均频谱，不是麦克风频响。 |

文字统一进行 NFKC、繁体转简体、忽略大小写/标点/空格。不会把“十五”和“15”自动当作等价，避免隐含规则掩盖错误；这种书写差异需要结合逐字对照人工复核。原稿不会输入 Whisper，不设置原稿提示词。固定 Whisper small、CPU、temperature=0、beam_size=5、condition_on_previous_text=False。

音质比较按场景分组，不同文案也能比较预测分数，但会显示内容及条件限制，不直接判定硬件优劣。没有正确原稿时 CER、内容保真分、关键词正确率均显示未测，独立转写不会当作标准答案。

相同设备重复结果先求均值，展示范围及原始每次结果。CER 至少低 1 个百分点且 DNSMOS 整体至少高 0.1 时才提示“两个指标均更优”；这是便于筛选的工程阈值，不是统计显著性。条件未确认、批次未完成时不判定硬件优胜；不跨不同原稿或场景给出总排名。模型质量评分失败时明确缺失，不以估算或零分填充。

没有干净参考录音，不计算 STOI / ESTOI / PESQ；没有盲听测试，不生成真实人工字错率或人工可懂度。自动报告辅助研发，正式结论应结合控制条件、足够的说话人/样机/重复次数和人工听辨。

## 字词与问题时间轴（v1.2）

识别启用 Whisper 原生词级时间对齐，每个字词或词组可点击回听；多字词组保留其共同时间范围，不通过均分时间伪造逐字精度。字符位置按转写中 Unicode 字母及数字计数，排除标点和空格，不代表正确原稿位置。个别字的起止时间可能相同，表示模型未分开边界，不能解释成真实发音时长为零。

疑似音频异常与低置信转写分别显示。削波、局部能量突变等采用明确的信号启发规则，只产生需要回听的候选；词语识别存疑不能直接证明收音不好。自然停顿、轻声和环境变化均可能产生类似信号。

DNSMOS 仍使用约 9.01 秒窗口和 1 秒步长。窗口可能覆盖多个字词；短录音只有 1～2 个窗口时，不会伪造逐秒或逐字音质分数，也不会声称某个字独立扣了多少分。整体音量偏低列为全局提示，不标成某个时刻突然变差。完整规则及时间精度随结果保存。

历史报告可点击“更新字词定位”，复用原件重新分析；原始录音保留，新的分析成功后才替换对应旧结果。无原稿时仍不计算 CER。

## 推荐录音方式

按真实佩戴或使用距离固定声源和设备位置；同一段 15～60 秒以上测试语音，包含不同说话人及数字/否定词。先做安静正常音量、轻声、稳定噪声、背景人声四场景，各录 3 次。每次记录增益、降噪、固件版本和距离。不要用不同位置/不同原稿的录音得出硬件优劣结论。少于 9.01 秒的音频按 DNSMOS 上游方法循环补齐，并在结果提示。

## 安装与运行

主要验证环境为 macOS，推荐 Python 3.12。需要 `ffmpeg`、`ffprobe` 和现代浏览器。后端基于 Python；其他系统尚未完成桌面使用验证。以下命令用于 macOS / Linux 风格的终端，macOS 双击入口单独提供。

macOS 安装系统依赖（已具备时跳过）：

```sh
brew install python@3.12 ffmpeg
```

克隆并安装：

```sh
git clone https://github.com/SvenKunkka/voicebench.git
cd voicebench
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt -r requirements-asr.txt
.venv/bin/python scripts/setup_models.py
.venv/bin/python launch.py
```

模型准备步骤首次需要联网，从官方地址下载约 484 MB 的 Whisper small 权重到 `~/.cache/whisper/`，校验 SHA-256；已有正确缓存会复用。约 1.2 MB 的 DNSMOS 模型已随仓库附带来源清单与许可。安装完成后，录音分析在本机完成。

以后可双击 **启动收音对比台.command**，或直接启动：

```sh
.venv/bin/python -m uvicorn app.server:app --host 127.0.0.1 --port 8767
```

然后打开 <http://127.0.0.1:8767>。这是供可信本机使用的工具，没有多用户身份认证，不应改成公网服务直接暴露。

也可以通过 `VOICEBENCH_WHISPER_PYTHON=/path/to/python` 复用已安装 Whisper 的独立环境。Whisper 安装在本项目 `.venv` 中时，无需先激活环境。

## 开发与验证

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests -q
node --check app/static/app.js
```

测试使用自行生成的音频，不要求下载 Whisper 权重；音频测试需要 FFmpeg。实际转写才需要 Whisper 与 PyTorch。源码在 `app/`，公开仓库不附带私人录音或真实转写报告。

## 数据与隐私

用户录音、原稿、结果和缓存保存在本机 `data/`。初次安装依赖和模型需要联网；分析过程不把录音发送给在线服务。导出文件可能包含转写，应在分享前核对。`data/`、`reports/`、验证材料、浏览器记录及音频文件都已加入 Git 排除规则。
